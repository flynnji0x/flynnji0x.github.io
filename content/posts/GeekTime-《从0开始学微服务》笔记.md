### 01 到底什么是微服务

- 单体应用架构的弊端
    - 部署效率低下
    - 团队协作开发成本高
    - 系统高可用性差
    - 线上发布变慢
- 什么是服务化
    - 通过服务化，可以解决单体应用膨胀，团队开发耦合度高，协作效率低下的问题
- 微服务相比于服务化有什么不同
    - 服务拆分粒度更细
    - 服务独立部署
    - 服务独立维护
    - 服务治理能力要求高


### 02 从单体服务应用走向服务化

- 服务化拆分的方式
    - 纵向拆分
        - 从业务维度角度进行拆分
    - 横向拆分
        - 从公共且独立功能维度拆分
- 服务化拆分的前置条件
    - 服务如何定义
    - 服务如何发布和订阅
    - 服务如何监控
    - 服务如何治理
    - 故障如何定位

### 03 初探微服务架构

- 微服务架构下，服务调用主要依赖下面几个基本组件
    - 服务描述
        - 常用的服务描述方式包括RESTful API，XML配置和IDL文件
        - RESTful API通常用于HTTP协议的服务描述
        - XML多用于RPC协议的服务描述
        - IDL文件通常用作Thrift和gRPC这类跨语言服务调用框架
    - 注册中心
![2021-07-15_224310](/image/GeekTime-《从0开始学微服务》笔记/2021-07-15_224310.png)
    - 服务框架
        - 发起调用前需要解决的问题
            - 服务通信采用什么协议
            - 数据传输采用什么方式
            - 数据压缩采用什么格式
    - 服务监控
        - 服务监控主要包括三个流程
            - 指标采集
            - 数据处理
            - 数据展示，数据可视化
    - 服务追踪
        - 原理
            - 发起调用前，生成一个requestid，作为请求传输的一部分，传递给服务提供者
            - 继续请求其他服务，在当前服务再生成一个自己的requestid，然后把两个requestid都作为请求参数继续往下传递
    - 服务治理
        - 经常会遇到的几种状况
            - 单机故障
            - 单IDC故障
            - 依赖服务不可用

### 04 如何发布和引用服务

- RESTful API
    - 适合跨业务平台之间的服务协议
- XML配置
    - 一般私有RPC框架会选择XML配置这种方式来描述接口
- IDL文件
    - interface description language
    - 主要用作跨语言平台的服务间的调用
    - Facebook开源的Thrift协议
    - Google开源的gRPC协议


### 05 如何注册和发现服务

- 微服务架构三个角色
    - 服务提供者
    - 服务消费者
    - 服务注册中心
- 注册中心的实现方式
    - 注册中心API
    - 集群部署
        - 开源注册中心zookeeper，从多个节点实例中选举出leader（Paxos协议），leader负责数据更新等操作（ZAB协议）
    - 目录存储
        - 注册中心存储服务信息一般采用层次化的目录结构
    - 服务健康状态检测
        - zk是基于客户端和服务端的长连接和会话超时控制机制实现服务健康状态检测的
    - 服务状态变更通知
        - zk的Watcher机制
    - 白名单机制
        - 提供白名单机制，只有白名单内的RPC Server才能够调用注册中心的注册接口

### 06 如何实现RPC远程服务调用
    - RPC，remote procedure call，远程过程调用
    - 服务调用需要解决的几个问题
        - 通信框架
            - 提供了基础的通信能力
        - 通信协议
            - 描述了通信契约
        - 序列化和反序列化
            - 用于数据的编解码

### 07 如何监控微服务调用
    - 监控对象可以分为四个层次：
        - 用户端监控
        - 接口监控
        - 资源监控
        - 基础监控
    - 监控指标
        - 请求量
            - 实时请求量，QPS，queries per second
            - 统计请求量，PV，page view
        - 响应时间
        - 错误率
    - 监控维度
        - 全局维度
        - 分机房维度
        - 单机维度
        - 时间维度
        - 核心维度
    - 对于有一个微服务来说，你必须明确要监控哪些对象，哪些指标，并且要从不同的维度进行监控，才能掌握微服务的调用情况
    - 监控系统原理
        - 数据采集
            - 通常有两种方式
                - 服务主动上报
                - 代理采集
        - 数据传输
            - 数据传输的两种方式
                - UDP传输
                - kafka传输
            - 一般采用的数据格式
                - 二进制协议
                    - 常用的是PB对象
                - 文本协议
                    - JSON字符串
        - 数据处理
            - 数据聚合的两种方式
                - 接口维度聚合
                - 机器维度聚合
            - 选择的数据库一般分为
                - 索引数据库，Elasticsearch
                - 时序数据库，openTSDB
        - 数据展示
            - 以dashboard的方式展示给用户，曲线图，饼状图等等
